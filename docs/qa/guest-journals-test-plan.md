# Тест-план: начатые журналы гостя

Ручная проверка для пользователя **без входа**. Составлено по коду ветки `cursor/guest-journal-photo-reset-37ab`.

Сообщения про HEIC и файл больше 20 МБ в этот пул-реквест не входят (отдельный PR #2). Здесь их не проверять как новую функциональность.

## Что должно работать

- Гость хранит **несколько** начатых журналов и открывает любой из списка.
- У каждого журнала свой токен галереи. Фото одного не попадают в другой.
- Нижняя кнопка «Продолжить» на выборе типа **открывает уже начатый** журнал этого типа, а не затирает его пустым.
- «Начать новый журнал» **добавляет** ещё один журнал, старые остаются в списке.
- Удаление миниатюры снимает это фото и со слотов разворотов.
- Вторая вкладка с тем же журналом показывает предупреждение. Если править в обеих, побеждает последнее сохранение.
- При входе **все** гостевые журналы, их страницы и галереи переносятся в аккаунт. Если перенос фото не удался, черновик остаётся и показывается ошибка, а не пустая галерея.
- Гостевой черновик живёт 14 дней.
- Если браузер не может записать черновик, пользователь видит ошибку.
- Фото галереи, к которой 14 дней никто не обращался, помечаются удалёнными на сервере.

## Где что лежит

DevTools → Application → Local Storage.

| Ключ | Содержимое |
| --- | --- |
| `pagesOfYou.localDrafts` | JSON-массив журналов. У каждого: `id` (он же `order.id`, вид `local-<uuid>`), `magazineTypeId`, `order` (страницы и расставленные фото), `trash`, `galleryGuestId`, `savedAt`, иногда `adoptedOrderId` (заказ уже создан, но перенос ещё не закончен). |
| `pagesOfYou.localDraft` | Старый ключ одного журнала. При первом чтении переносится в массив и удаляется. |
| `pagesOfYou.guestId` | Постоянный UUID браузера для лимита AI. **Не** ключ галереи и при новом журнале не меняется. |
| `pagesOfYou.draftLock` | `{ draftId, tabId, at }` — какая вкладка держит журнал открытым. |
| `accessToken`, `refreshToken`, `authUser` | Только после входа. У гостя их быть не должно. |

Самих файлов в `localStorage` нет, только URL. Фото на сервере с `guestId` = `galleryGuestId` этого журнала.

Запросы:

- `POST /api/files/image` — поле `guestId` равно токену **этого** журнала;
- `GET /api/files?guestId=<токен>`;
- `POST /api/files/guest-gallery/touch` — при сохранении черновика, чтобы фото не попали под очистку;
- после входа `POST /api/files/claim-guest-photos`, дальше список уже с `orderId`.

Очистка брошенных фото: гостевой файл без заказа удаляется (soft-delete), если галерею не трогали 14 дней. «Трогали» — это `guestTouchedAt` (ставится при загрузке и при touch). Если метки нет, считается `createdAt`. Очистка запускается при чтении или touch гостевой галереи, отдельного крона нет (вопрос владельцу в конце).

Срок черновика: 14 дней от `savedAt`. Другая `schemaVersion` тоже выбрасывается. Просроченный журнал исчезает из списка, остальные остаются.

## Предусловия

1. Обычное окно, не приватный режим (приватный — отдельный кейс).
2. Очистить для этого сайта `pagesOfYou.localDrafts`, `pagesOfYou.localDraft`, `pagesOfYou.guestId`, `pagesOfYou.draftLock`, `accessToken`, `refreshToken`, `authUser`.
3. Обновить страницу. В шапке главной — **«Войти»**, не иконка кабинета.
4. Два визуально разных снимка JPEG или PNG, каждый меньше 20 МБ: кадр «A» и кадр «B». Для третьего журнала — кадр «C».
5. Желательно два типа журнала. Если тип один, несколько журналов всё равно создаются, адреса `local-…` будут разными.
6. Во вкладке Network не фильтровать `files`.

Фото «на месте», если совпали все три пункта: счётчик «Загружено N фото», те же миниатюры, те же кадры в слотах разворотов. Первые загрузки сами встают в пустые слоты **не обложки**.

Две кнопки «Продолжить»:

- в модалке у карточки журнала — открыть **этот** журнал;
- внизу страницы выбора типа — открыть уже начатый журнал выбранного типа, если он один; если их несколько, снова показать список; если такого типа ещё нет — создать новый. Пустой журнал поверх старого она не создаёт.

«Начать новый журнал» в модалке разрешает нижнему «Продолжить» создать **ещё один** журнал, не удаляя список.

## Кейсы

### 1. Журнал A с фото

1. С чистого storage: главная → «Создать журнал». Модалки нет.
2. Выбрать тип 1, нижнее «Продолжить».
3. Загрузить 2 кадра «A».

Ожидание:

- Счётчик 2, на разворотах кадры «A».
- `guestId` в `POST /api/files/image` и в `GET /api/files` один и тот же. Записать его как токен A.
- В `pagesOfYou.localDrafts` один элемент, его `galleryGuestId` = токен A, `id` начинается с `local-`.
- `pagesOfYou.guestId` появился и **не равен** токену A.
- Ключей входа нет.
- Есть `POST /api/files/guest-gallery/touch` с тем же `guestId`.

### 2. Вернуться в A

1. Уйти на главную, снова «Создать журнал».
2. Модалка с одним журналом типа 1. «Продолжить» на карточке.

Ожидание: тот же A, кадры «A», токен A не изменился. Кадров «B» нет.

Со шага фото «Назад» на выбор типа может снова показать модалку. «Продолжить» на карточке опять открывает A.

### 3. Второй журнал B пустой, A остаётся

1. Из A: главная → «Создать журнал».
2. «Начать новый журнал». Список в storage **не** очищается: оба ключа `pagesOfYou.localDrafts` и `pagesOfYou.guestId` на месте, в массиве по-прежнему A.
3. Выбрать тип (лучше тип 2, можно тот же тип 1) и нижнее «Продолжить».
4. Ничего не загружать.

Ожидание:

- «Загружено 0 фото», кадров «A» нет.
- В массиве **два** журнала. У нового `galleryGuestId` — токен B, не токен A и не `pagesOfYou.guestId`.
- `GET /api/files?guestId=` для B пустой.
- `pagesOfYou.guestId` прежний.

### 4. В B другие фото

Загрузить 2 кадра «B».

Ожидание: счётчик 2, только «B». Токен в запросах — B. В элементе B в storage URL кадров «B», URL «A» нет.

### 5. Снова открыть A, потом B

1. Главная → «Создать журнал».
2. В модалке две карточки. Открыть A.

Ожидание: кадры «A», токен A, кадров «B» нет.

3. Вернуться и открыть B.

Ожидание: кадры «B», токен B, кадров «A» нет.

Нижнее «Продолжить» без «Начать новый», если для выбранного типа журнал ровно один, открывает его, а не пустой. Если для типа уже два журнала, нижнее «Продолжить» снова показывает список, а не создаёт третий пустой.

### 6. Удаление миниатюры снимает фото со слотов

1. В B два кадра, оба стоят на разворотах.
2. Удалить один.
3. Уйти на главную и снова открыть B. Затем открыть A.

Ожидание:

- В B остался второй кадр и в галерее, и на развороте. Удалённый не виден ни миниатюрой, ни в слоте.
- A не изменился: оба кадра «A» на месте.
- Запрос удаления шёл с `guestId` = токен B.

### 7. Обновление страницы

На открытом B нажать F5 на адресе `/order/local-…/photos`.

Ожидание: текст «Черновик заказа был потерян (например, из-за обновления страницы) — начните заново.» Массив `pagesOfYou.localDrafts` на месте.

«Начать заново» → в списке и A, и B. Открыть B: кадры «B» на месте.

### 8. Закрыть вкладку и открыть сайт снова

Закрыть вкладку, не очищая данные сайта. Открыть сайт → «Создать журнал» → открыть A и B по очереди.

Ожидание: оба журнала и их фото на месте. Токены те же. Полное закрытие браузера в обычном профиле — то же самое.

### 9. Третий журнал

«Начать новый» → тип → нижнее «Продолжить» → кадр «C».

Ожидание: в списке три журнала. У C свой токен. A и B открываются со своими фото.

### 10. Нижнее «Продолжить» не затирает журнал

1. Есть живой A.
2. «Создать журнал», закрыть модалку крестиком (не «Начать новый»).
3. Выбрать тип A и нажать нижнее «Продолжить».

Ожидание: открывается A с фото, новый пустой журнал не создаётся, длина массива не растёт.

Повторить после «Начать новый»: нижнее «Продолжить» создаёт дополнительный журнал, A в списке остаётся.

### 11. Две вкладки

1. Вкладка 1: открыт A.
2. Вкладка 2: открыть тот же A из списка.

Ожидание: жёлтая плашка «Этот журнал открыт в другой вкладке. Если править в обеих, сохранится последняя правка.» Хотя бы на одной из вкладок. В storage ключ `pagesOfYou.draftLock` с `draftId` журнала A.

3. Во вкладке 2 загрузить ещё один кадр. Во вкладке 1, не обновляя её, тоже изменить журнал (удалить или добавить кадр).
4. Обновить обе и открыть A заново.

Ожидание: остаётся состояние **последнего** сохранения. Галерея A не смешивается с B. Предупреждение не блокирует правку.

Закрыть вкладку 2 и подождать около 15 секунд: плашка на вкладке 1 пропадает (блокировка протухает).

### 12. Вход переносит все журналы

Нужен тестовый аккаунт.

1. Гостем иметь A и B с разными фото.
2. Войти через «Войти», затем «Создать журнал».

Ожидание:

- `pagesOfYou.localDrafts` исчез.
- Модалка уже про заказы аккаунта («У вас есть незаконченные журналы»), адреса **без** `local-`.
- В кабинете «Мои журналы» есть оба. У каждого свои фото и в галерее, и на разворотах.
- Список фото запрашивается с `orderId`, не со старым `guestId`.
- В Network был успешный `claim-guest-photos` для каждого токена.

Если сеть оборвать на claim (офлайн после появления заказа, или заблокировать `claim-guest-photos`): сообщение «Не удалось перенести… Черновики сохранены», массив `localDrafts` остаётся, у журнала может появиться `adoptedOrderId`. Повторить уже онлайн: тот же заказ дозаполняется, второй заказ не создаётся, фото на месте, после успеха локальный список пуст.

### 13. Вход с шага оформления

Гостем дойти до проверки журнала и оформить заказ, войдя в предложенной форме.

Ожидание: текущий журнал становится заказом, фото на страницах те же, галерея заказа не пустая. Остальные гостевые журналы тоже становятся черновиками аккаунта, а не пропадают.

### 14. «Начать новый» у вошедшего

1. Войти, имея черновик с фото.
2. «Создать журнал» → «Начать новый» → тип → нижнее «Продолжить».

Ожидание:

- Новый заказ: «Загружено 0 фото». В Network новый `orderId`.
- Старый черновик в кабинете и в модалке на месте, его фото не изменились.
- Загрузить в новый другие кадры. Удалить один в новом. В старом все кадры на месте.

«Начать новый» у вошедшего не удаляет серверные черновики.

### 15. Обрыв загрузки

В журнале уже есть один кадр. Начать загрузку ещё пары и выключить сеть на середине. Вернуть сеть, открыть журнал из списка.

Ожидание: успешный кадр на месте и после повторного открытия. Оборванный в галерее не появляется. После восстановления сети тот же файл загружается как новый. Дослать оборванный запрос нельзя.

### 16. Очищенный storage и срок 14 дней

1. Удалить только `pagesOfYou.localDrafts`, `pagesOfYou.guestId` не трогать. Обновить и открыть создание.

Ожидание: списка нет. Новый журнал пустой, старые фото не подхватываются (у него новый токен).

2. В живом массиве поставить одному журналу `savedAt` старше 15 дней, второму оставить свежую дату. Открыть создание.

Ожидание: в списке только свежий. Его фото на месте. Просроченный не предлагается и его фото в свежий не попадают.

3. Поставить одному `schemaVersion: 999`.

Ожидание: эта запись выбрасывается, остальные журналы целы.

### 17. Хранилище недоступно или переполнено

Приватное окно либо заполненная квота origin (в консоли можно подменить `localStorage.setItem`, чтобы он бросал ошибку, если квоту занять нечем).

Начать журнал и изменить его так, чтобы он сохранился (загрузить фото или дойти до шага фото).

Ожидание: модалка «Черновик не сохранён» и текст, что хранилище недоступно или переполнено. Страница не падает. После перезагрузки несохранённого журнала в списке нет.

### 18. Брошенные фото на сервере

Это не ждать 14 дней вручную. Достаточно убедиться по коду/запросам, что сохранение шлёт `guest-gallery/touch`, и по базе (если есть доступ): у свежезагруженного файла `guestTouchedAt` заполнен, у файла с `guestTouchedAt` или `createdAt` старше 14 дней, без `orderId`, после любого `GET /api/files?guestId=…` или touch проставлен `deletedAt`.

Фото, уже привязанные к заказу (`orderId` есть), не удаляются.

## Вопрос владельцу

Очистка брошенных гостевых фото запускается, когда кто-то читает или «трогает» гостевую галерею. Отдельного ежедневного задания нет: если гость больше никогда не откроет сайт, его старые файлы останутся, пока такой запрос не случится. Нужен ли отдельный cron?
